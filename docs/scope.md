# LearnRise 范围冻结文档

第十一届华为 ICT 大赛 · 创新赛 · 赛题一：基于华为云产品打造 AI 创新应用

本文件是 MVP 的范围契约。任何新增需求先对照本文件判断归入 IN、OUT 还是 DROP ORDER，不允许在交付前临时加模块。冻结日期 2026-10-31，MVP 交付 2026-11-10，初赛 2026-12，华为云 kill-switch 2026-11-25。

团队配置：1 名开发者 + 3 名学生 + 1 名指导老师。所有范围决策默认按这个人力预算评估，不按"理想团队"评估。

---

## IN

MVP 必须交付以下内容。少一项即视为未完成交付。

**8 个 P0 模块**

1. **多模态摄入**：上传 PDF / 图片，后台任务解析、文本抽取、OCR 兜底，状态机 `queued → parsing → embedding → ready`。
2. **RAG 知识库**：文档切块、向量化、入库、按用户检索，返回 chunk 级原文片段与来源定位。
3. **结构化笔记**：从文档生成层级笔记树（章节 → 要点 → 细节），可读、可保存。
4. **思维导图**：render-only，JSON 树直接渲染为 ECharts tree，不做拖拽编辑。
5. **智能出题**：基于知识库内容生成选择题，含题干、选项、正确答案、解析。
6. **DSR 间隔重复复习**：卡片队列、翻转、1 到 5 评分、到期日按 DSR 公式更新。
7. **邮件提醒**：每日到期卡片汇总邮件，独立调度进程触发。
8. **学习仪表盘**：4 个 KPI 卡片 + 章节热力图 + 掌握度雷达 + 遗忘曲线。

**用户可视化 Agent 配置**

- 字段：名称、`base_url`、`api_key`、`model`、`system_prompt`、`temperature`、是否默认标记。
- `api_key` 落库前加密，回显一律掩码。
- 支持多 Agent 并存，用户可切换默认 Agent。
- 知识点 AI 讲解走 SSE 流式输出，前端逐 token 渲染。

**Provider 适配器层**

- 统一接口 `Embedder` / `Chat` / `OCR`，实现可插拔。
- `PROVIDER_PROFILE=local` 与 `PROVIDER_PROFILE=huawei` 双 profile，同一套业务代码零改动切换。
- 两个 profile 的 parity 测试都必须通过（见 Metrics）。

**认证与数据隔离**

- 注册 / 登录 / 会话。
- 所有业务表带 `user_id`，查询强制 ownership 校验，跨用户读取必须返回 404 而非 403。

**本地与演示**

- Docker Compose 一键启动全部服务（API、worker、OCR、Postgres、调度器、前端）。
- `make demo` 三分钟内拉起完整演示环境，预置 seed fixtures。

**华为云真实部署**

- Phase B 真实部署到华为云（ECS / RDS / OBS / MaaS / OCR / CodeArts）。
- 保留 CodeArts 使用证据：仓库、流水线、构建记录截图。
- 初赛四件套：Template 1 提交表、设计文档、答辩 PPT、不超过 3 分钟演示视频。

## OUT

以下内容明确不做。每条都写清理由，避免评审或队友反复追问。

| 不做的东西 | 理由 |
| --- | --- |
| **学习路径 DAG** | 改为静态有序列表。DAG 需要拓扑排序、前置依赖校验、环路检测三套逻辑，收益只在"看起来聪明"，演示里观众看不出差别。 |
| **可编辑思维导图** | 仅 render-only：JSON 树 → ECharts tree。编辑意味着节点增删改、布局重算、撤销栈、持久化冲突，工作量是渲染的 5 倍以上。 |
| **浏览器插件** | 需要 Chrome / Edge 双端打包、商店审核、注入脚本兼容，与核心闭环无关。 |
| **Redis** | 缓存与队列用 Postgres 表 + APScheduler 足够，MVP 流量撑得住，多一个中间件就多一个故障点。 |
| **CDN** | 静态资源直接由 ECS 的 Nginx 提供。CDN 需要备案与回源配置，且会打断 SSE（见 Risk 第 5 条）。 |
| **DLV (数据可视化)** | 仪表盘用 ECharts 自绘即可，DLV 需要额外权限与数据集编排，纯增成本。 |
| **移动端** | 只做响应式 Web，不做 App、不做小程序。三个学生没有移动端经验。 |
| **i18n** | 单一中文界面，不做多语言资源文件与切换逻辑。初赛评审是中文环境。 |
| **多租户共享** | 只做 per-user 隔离，不做组织、团队、共享知识库、权限矩阵。 |
| **PDF 导出** | 笔记与错题不导出 PDF。导出需要排版引擎与字体嵌入，演示脚本里没人看。 |
| **MVP 内 rerank / BM25 / query rewrite** | 纯向量检索先跑通。rerank 仅保留 feature flag，默认关闭；BM25 与 query rewrite 完全不实现。混合检索的调参时间远超收益。 |
| **第二调度器 (SM-2 / FSRS)** | DSR 一个算法足够。SM-2 与 FSRS 只保留接口签名，不实现算法体，避免"三套调度互相打架"。 |
| **承诺 FULL TDD 覆盖率数字** | 不承诺任何覆盖率百分比。测试按风险写：认证、隔离、provider parity、状态机必测；UI 与渲染不强求。写死数字只会逼人造假。 |

## DROP ORDER

时间不够时按下列顺序从上往下砍，不允许跳序。每项都给出触发条件，触发后立刻执行，不做讨论。

1. **浏览器插件**
   - 触发条件：距交付 < 10 天仍未开始。
   - 动作：从仓库与文档中移除，不留半成品目录。

2. **学习路径 DAG**
   - 触发条件：距交付 < 7 天，或拓扑排序 + 依赖校验未通过集成测试。
   - 动作：降级为静态有序列表，前端只渲染 `<ol>`。

3. **可编辑导图**
   - 触发条件：距交付 < 6 天，或节点编辑后再渲染出现布局错乱。
   - 动作：锁定为 render-only，隐藏所有编辑入口。

4. **rerank / 混合检索**
   - 触发条件：距交付 < 5 天，或检索延迟超过 800ms。
   - 动作：feature flag 置 false，代码保留，配置关闭。

5. **多 Agent provider 类型**
   - 触发条件：距交付 < 4 天，或第二家 provider 的 parity 测试连续两次失败。
   - 动作：只保留 OpenAI 兼容协议一种，其余适配器标注 TODO 不接线。

6. **仪表盘扩展**
   - 触发条件：距交付 < 3 天仍未完成。
   - 动作：只留 4 KPI + 一张图，热力图、雷达、遗忘曲线全部砍掉。

## 3-min Storyboard

固定 7 个镜头，总时长 180 秒，分秒不超。旁白提前录好，画面跟着旁白走，不即兴。

| 镜头 | 时间 | 操作 | 预期屏幕输出 | 时长 |
| --- | --- | --- | --- | --- |
| 镜头 1 | 0-20s | 上传一个 20 页 PDF | 进度条依次显示 `queued → parsing → embedding → ready`，结束后提示"可检索" | 20s |
| 镜头 2 | 20-50s | 点击生成笔记与导图 | 左侧笔记树逐层展开（章节 / 要点 / 细节），右侧 ECharts 导图渲染出至少 3 个节点 | 30s |
| 镜头 3 | 50-80s | 点击智能出题 | 页面渲染 3 道选择题，题干、4 个选项、正确答案与解析均可见 | 30s |
| 镜头 4 | 80-110s | 故意答错第 1 题 | 展示解析、chunk 级原文片段（高亮命中句）、提示"已加入复习卡片" | 30s |
| 镜头 5 | 110-140s | 进入复习页 | 卡片翻转显示答案，评分按钮 1 到 5，点击后到期日立即更新并提示下次复习时间 | 30s |
| 镜头 6 | 140-165s | 打开学习仪表盘 | 4 个 KPI 数字 + 章节热力图 + 掌握度雷达 + 遗忘曲线同屏可见；旁白里插入邮箱提醒的静态截图 | 25s |
| 镜头 7 | 165-180s | 打开知识点讲解 | 下拉框选中一个 Agent，首 token 在 3 秒内出现，正文流式逐字输出 | 15s |

合计 180 秒。邮箱提醒不单独占镜头，只在镜头 6 以静态截图 + 一句旁白带过，这是为了守住 180 秒上限。

## Metrics

验收全部可量化，主观描述一律不算数。

| 指标 | 目标 | 测量方式 |
| --- | --- | --- |
| 上传到可检索 | ≤ 60s（20 页 PDF） | 演示环境计时，从点击上传到状态 `ready` |
| 出题耗时 | ≤ 10s（生成 3 题） | 后端接口耗时日志 |
| 讲解首 token | ≤ 3s | 前端记录 SSE 首个 token 到达时间 |
| Profile parity | `PROVIDER_PROFILE=local` 与 `=huawei` 双双全绿 | 同一套 parity 测试跑两遍，两次均 exit 0 |
| 检索命中率 | 由 `bench/` 脚本产出 | `bench/` 跑固定 fixture，输出 JSON |
| 邮件到达率 | 由 `bench/` 脚本产出 | 同上，统计成功投递比例 |

硬性规则：检索命中率与邮件到达率必须由 `bench/` 脚本跑出来，禁止手写数字写进文档或 PPT。任何在文档里出现的人工估算值，视为无效指标。

## Risk & Guardrails

以下 12 条来自 Metis 评审修正，逐条落地，不做删减。

1. **DeepSeek 官方无 embeddings**。Phase A 改用 `bge-m3 @1024` 维（SiliconFlow / 百炼），维度与华为云 MaaS 的 BGE-M3 保持一致，Phase B 切换时不需要重新嵌入全库。这是双 profile 能 parity 的前提。

2. **OCR 与 MaaS 区域分裂**。华为云 OCR 在 `cn-north-4`，MaaS 在 `cn-southwest-2`。主区域定为 `cn-north-4`，MaaS 跨区域调用走 EIP / NAT 网关，并把跨区域流量成本单独记账，写进成本表。

3. **扩展创建方式不同**。本地是 `CREATE EXTENSION vector`，RDS 走 `control_extension` 控制台参数，两者不能共用一段迁移脚本。做法是 per-profile bootstrap：本地用 init 脚本，RDS 用控制台操作，Alembic 迁移里绝不建扩展，只建表。

4. **OCR 独立容器 + 固定 Python 版本**。OCR 服务单独一个容器，Python 固定 `3.11.9`。宿主 Python 3.14 与 Paddle 不兼容，禁止在宿主机直接装 OCR 依赖。

5. **SSE 不能走 CDN / OBS**。流式接口必须 API 直连 ECS / EIP 子域，Nginx 关闭 `proxy_buffering` 与 `gzip`。任何把 SSE 放到 CDN 或 OBS 后面的方案直接否决。

6. **Phase B 不能放最后一波**。华为云不能等到最后再上，否则合规风险集中爆发。Day 0 就做 canary 部署验证，之后每一 wave 都跑一次完整 parity，`2026-11-25` 设为 kill-switch 截止日：到那天还没通过的 wave，回退到 `PROVIDER_PROFILE=local` 并记录原因。

7. **砍范围清单常备**。DAG、可编辑导图、浏览器插件、Redis、CDN、rerank、第二调度器、ModelArts、DLV、移动端、i18n、多租户、PDF 导出。这 13 项任何时候都被视为可牺牲，出现排期冲突先砍这个清单里的东西。

8. **Agent 安全**。`base_url` 走 SSRF allowlist，只允许配置白名单内域名与协议；`api_key` 掩码 round-trip 测试（存进去再读出来，前端只能看到掩码）；日志全链路脱敏，禁止打印密钥与完整 prompt；所有资源读取做 ownership 校验。

9. **调度器防重复发信**。APScheduler 必须跑在独立进程，或多 worker 场景下用 Postgres advisory lock 抢占。多 worker 同时触发同一批邮件属于必须避免的故障。

10. **每 wave 留证据 + CodeArts 首日建仓**。每个 wave 产出写入 `.sisyphus/evidence/<wave>/`，包含命令输出与截图。CodeArts 仓库第一天就建，不要等代码写完再补，否则提交历史造假痕迹明显。

11. **可复现**。README 写清 provider 矩阵（哪个 profile 用哪个模型与维度）、提交 lockfile、seed fixtures 固定、`make demo` 一条命令可复现演示。所有 bench 数字必须由脚本产出并可重跑。

12. **演示脚本决定范围**。先写死 3 分钟演示脚本，范围以脚本为准。没有脚本，范围一定会按模块清单无限膨胀，这是本项目最大的范围风险。
