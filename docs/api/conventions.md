# LearnRise API 统一约定

> 本文件为**手写**文档，不受 `scripts/gen_api_docs.py` 管理。
>
> **适用范围：仅新增端点。** 存量端点（本约定落地前已存在的 33 个操作）继续保持原有契约，见下文「存量契约冻结」。

## 1. 路径与资源命名

- 所有业务端点以 `/api` 为前缀，例如 `/api/sources`、`/api/quiz/generate`。
- 仅内部任务（cron / 运维回调）使用 `/internal` 前缀，不对公网暴露。
- 资源名使用**复数名词**、小写 kebab-case：`/api/knowledge-points`、`/api/competitions`。
- 集合与单例分离：集合 `GET /api/sources`，单体 `GET /api/sources/{source_id}`。
- 动词型操作用子路径表达：`POST /api/sources/{source_id}/reprocess`、`POST /api/quiz/{question_id}/answer`。
- 新路径不得复用存量路径去承载不同语义；需要变更语义时新增路径。

## 2. 错误响应

### 2.1 统一结构

新端点的错误体在 FastAPI 默认结构上**追加** `code` 字段：

```json
{
  "code": "NOT_FOUND",
  "detail": "资源不存在"
}
```

- `detail` 保留人类可读文案，供前端直接展示或兜底。
- `code` 为稳定的机器可读枚举，前端据此分支处理，不解析 `detail` 文本。
- `code` 只能**新增**，不得修改既有含义；新增取值需同步更新本文件。

### 2.2 `code` 取值表

| `code` | HTTP | 含义 |
|---|---|---|
| `AUTH_REQUIRED` | 401 | 未携带凭证、凭证过期或无效 |
| `FORBIDDEN` | 403 | 已认证但确无操作权限（仅在无法用 404 隐藏资源时使用） |
| `NOT_FOUND` | 404 | 资源不存在，或当前用户不可见（含跨租户/非成员） |
| `VALIDATION_ERROR` | 422 | 请求体或参数校验失败 |
| `CONFLICT` | 409 | 与现有资源状态冲突（如重复操作） |
| `RATE_LIMITED` | 429 | 触发限流 |
| `EMAIL_TAKEN` | 409 | 注册/改绑邮箱已被占用 |
| `NO_CONTEXT` | 400 | 缺少可用的上下文（如资料未解析出文本） |
| `PLAN_NOT_READY` | 409 | 学习计划尚未生成完成 |
| `EXAM_EXPIRED` | 410 | 考试/答题会话已过期 |
| `SESSION_LIMIT` | 409 | 并发会话数达到上限 |
| `JOIN_INVITE_INVALID` | 400 | 竞赛邀请码无效或已失效 |
| `ALREADY_MEMBER` | 409 | 已是该竞赛成员，无需重复加入 |

`code` 是**附加**字段：存量端点不返回它，前端必须容忍其缺失。

## 3. 存量契约冻结

- 现有 **33 个操作**（见 `openapi.json` 的 paths/operations）保持**路径、HTTP 状态码、`detail` 文案逐字不变**。
- 不得为存量端点改写错误体的 `detail`，也不得把它改成新的 `{code, detail}` 结构。
- `code` 字段**只允许出现在新增端点**上；存量端点如需补充能力，应新增端点而非改写旧响应。
- 新增端点沿用旧的 `detail` 文案风格（中文、面向用户、不泄露内部实现）。

## 4. 分页

- 列表端点统一使用 `limit` / `offset` 查询参数：
  - `limit`：每页条数，默认由端点决定并写入 OpenAPI 默认值，需设上限。
  - `offset`：偏移量，从 0 开始。
- 列表响应体仍为数组（不在 body 外包一层分页对象）；总数通过响应头返回：

```http
X-Total-Count: 128
```

- 前端据此计算页码；后端不得在分页缺失时静默截断而不给出总数。

## 5. 时间与格式

- 所有时间戳使用 **ISO-8601 UTC 带时区偏移**，例如 `2026-01-01T00:00:00+00:00`；禁止裸本地时间或 Unix 秒。
- ID 使用字符串形式的 UUID（`format: uuid`）。
- 金额/大小等数值字段在字段名中带单位（如 `size_bytes`、`response_time_ms`）。
- 布尔字段使用 `is_` / `has_` 前缀，避免否定式命名。

## 6. 鉴权与授权语义

- 认证方式：`OAuth2PasswordBearer`（`tokenUrl=/api/auth/login`），即请求头 `Authorization: Bearer <JWT>`。
- 未认证统一返回 **401**，并带 `WWW-Authenticate: Bearer`。
- **资源不可见一律返回 404，而不是 403**：跨租户、非成员、他人私有资源都按“不存在”处理，避免泄露资源是否存在。这与存量 `require_owner` 约定一致。
- 403 仅用于“用户已能确认资源存在、但确实无权执行该操作”的场景（如成员尝试删除共享内容）。
- 个人数据（笔记、错题、复习记录、个人智能体配置）始终仅所有者可读写。

## 7. 题型映射（前端 ↔ 后端）

前端题型与后端 `quiz.type` 的映射如下，新增端点与前端请求层必须遵守：

| 前端题型 | 后端 `type` | 说明 |
|---|---|---|
| `multiple` | `choice` | 选择题；多选按**选项集合**判分（忽略顺序，集合相等即正确） |
| `blank` | `short_answer` | 填空题/简答题；按文本规范化后比对 |
| `both` | 拆分为两道题 | 生成时拆成一道 `choice` + 一道 `judge`，分别持久化 |
| `judge` | `judge` | 判断题 |

- **未知题型必须直接拒绝**（返回 422 / `VALIDATION_ERROR`），不得静默丢弃或降级为其他题型。
- 后端 `choice` 的多选判分以选项集合为准，不允许按字符串全等比较。

## 8. 竞赛权限模型

竞赛内角色与权限：

| 角色 | 权限 |
|---|---|
| `leader` | 管理成员（邀请/移除/改角色）、编辑竞赛信息、删除共享内容 |
| `member` | 读取共享题库、上传资料、创建题目 |
| `viewer` | 只读共享内容 |

- 个人数据（个人笔记、个人答题记录）**始终仅所有者可见**，不因竞赛角色而共享。
- 非成员访问竞赛资源返回 **404**；成员越权执行 leader 操作返回 **403**（`FORBIDDEN`）。
- 角色变更即时生效；被移除的成员立即失去共享资源访问权。

## 9. 竞赛容量（`capacity`）

- `capacity` 为 `integer | null`，`null`（或 `0`）表示**不限制人数**，前端展示为「不限」。
- 本轮**不校验**容量：达到容量也不会拒绝加入，`COMPETITION_FULL` 不再返回。
- 客户端应把 `capacity <= 0` 与 `null` 同等处理，不得渲染为 `1/0`。
